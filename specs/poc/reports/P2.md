## 1. คำถาม

SymPy + LLM ตัดสินถูกผิดและจำแนก error ได้ตามเป้าไหม

## 2. วิธีทดสอบ

- **Data:** golden set 50 คำตอบ (`evals/answers/labels.jsonl`) · 30 ข้อจากรูปลายมือของ 5 คน (บรรทัดคำตอบใช้เฉลยลายมือของ P1 คือถือว่าผู้ใช้ยืนยันบรรทัดแล้วตาม AM-02) · 20 ข้อเป็นคำตอบพิมพ์ (writer `w06`) เขียนให้ครบทุก error type ตามโควตา · `expression` 30, `equation` 11, `factored` 9 · verdict: `incorrect` 24, `correct` 22, `incomplete` 2, `correct_with_flaw` 2
- **Label:** ทีม (May + Jam) ตกลงให้ AI (Claude) ร่าง label ทั้ง 50 ข้อและคำตอบพิมพ์ 20 ข้อ (PR #52 · `evals/answers/worksheet.md`) ตามคู่มือใน `evals/README.md`
- **ขั้นตอน:** แต่ละข้อผ่าน pipeline เดียวกับที่ห้องติวจะใช้ คือ SymPy ตรวจรายบรรทัด → hint `sign_flip_detected` → `ai.call("check_answer")` (tier `mid`, temperature 0, `thinking: low`) → merge rules · ให้คะแนนด้วย `run_eval.py` ตามนิยามที่ทีมตกลง (PR #47): verdict หารด้วย 50 ข้อ · error_type หารด้วย 28 ข้อที่ label ไม่ใช่ `correct` · first_wrong_line หารด้วย 24 ข้อที่ label มีเลขบรรทัด
- **สิ่งที่ไม่ได้ทดสอบ:** อ่านลายมือจากรูปจริงต่อกับ checker (ใช้บรรทัดที่ label ไว้ ไม่ใช่ผล OCR) · `method` (`doc`/`other`) เพราะไม่มีวิธีของชีทใน golden set และไม่อยู่ในเกณฑ์ P2 · model อื่นนอกจาก Gemini flash · Vertex และ key แบบจ่ายเงิน (free tier ทั้งหมด)

**ที่เจอตอนรันจริง (28 ต.ค.)**

- free tier ให้ 5 request ต่อนาทีต่อ model · gateway ไม่รอ rate limit นานกว่า `max_retry_wait_seconds` (10 วินาที · ตั้งไว้สำหรับห้องแชท) จึงได้ 429 แทบทุกข้อ · แก้ที่ `run_checker.py`: เว้น 13 วินาทีต่อข้อ, รอ 60 วินาทีเมื่อ 429, `--resume`
- default thinking ของ Gemini 3 ทำให้ timeout 15 วินาที → `config/ai.yaml` 1.3 `check_answer` เพิ่ม `thinking: low` (Jam ok · ไฟล์ร่วม)
- เพดาน request ต่อวันของ free tier ไม่พอรัน 50 ข้อพร้อม retry ในวันเดียว
- error 429 รายงานชื่อ model เป็น `gemini-3.6-flash` ทั้งที่ override เป็น `gemini-3.5-flash` · น่าจะเป็น alias ฝั่ง Google · ต้องยืนยันก่อนสรุปว่าวัด model ไหน
