## 1. Context

ผู้ใช้ส่วนใหญ่ใช้ iPad และคอม (Jam 9 พ.ย.) · ทุกวันนี้ต้องเขียนบนกระดาษ ถ่ายรูป แล้วแนบด้วยปุ่ม 📷 · feature นี้ให้เขียนวิธีทำบน canvas ใต้การ์ดโจทย์ได้ทันที ด้วยเมาส์, Apple Pencil หรือนิ้ว หรือใส่รูปแล้วเขียนทับ · ส่งแล้วเดินทางเดิมของรูปทั้งหมด (อัปโหลด → `ocr_preview` → ยืนยัน → ผลตรวจ) จึงไม่ต้องแก้ API · ทำในหน้าเว็บอย่างเดียว

## 2. Behavior

**ขึ้นเมื่อไหร่**

1. ใต้การ์ดโจทย์**ใบล่าสุด**ในรายการข้อความมี canvas 1 อัน (โจทย์ตอนเปิดห้องและโจทย์ข้อต่อไป) · การ์ดโจทย์ใบก่อนๆ ไม่มี canvas · ไม่มีการ์ดโจทย์ → ไม่มี canvas (แชทปกติ)
2. โจทย์ใบใหม่มา → canvas ใหม่ว่างใต้ใบใหม่ · canvas เดิมหายพร้อมสิ่งที่เขียน (ส่งไปแล้วอยู่ในการ์ดยืนยันลายมือ)
3. ช่องพิมพ์และปุ่ม 📷 ใน Composer ยังใช้ได้เหมือนเดิม

**เขียน**

4. canvas กว้างเต็มการ์ด สูง `CANVAS_HEIGHT_PX` (ค่าของ UI · 320) · พื้นขาว · คมบนจอความละเอียดสูง (ขนาดจริงคูณ `devicePixelRatio`) · `touch-action: none` (ลากนิ้วแล้วไม่เลื่อนหน้า)
5. Pointer Events: `pointerdown` เริ่มเส้น · `pointermove` ต่อเส้น · `pointerup` / `pointercancel` / `pointerleave` จบเส้น · นับเฉพาะ pointer หลัก (`isPrimary`) · ใช้ได้ทั้ง `mouse`, `pen`, `touch`
6. **ไม่วาดตามฝ่ามือ:** เมื่อ canvas นี้เคยมีเส้นจาก `pen` แล้ว pointer ชนิด `touch` ถูกเมิน (วางมือบนจอขณะใช้ Apple Pencil) · ก่อนมีปากกา นิ้ววาดได้
7. ความหนา: ปากกา `PEN_WIDTH_PX` (2.5) × แรงกด · แรงกดจาก `pen` ใช้ `pressure` (0–1 คูณ 2 แล้วจำกัด 0.5–2 เท่า) · `mouse` และ `touch` ใช้ความหนาเดียว (×1) · ยางลบ `ERASER_WIDTH_PX` (18) ลบเฉพาะเส้น (ไม่ลบรูปพื้นหลัง)

**เครื่องมือ** (แถวปุ่มใต้ canvas · ทุกปุ่มมี `aria-label` · ข้อความอยู่ใน `strings.ts`)

8. **ปากกา** / **ยางลบ** สลับกัน (`aria-pressed`) · เริ่มที่ปากกา
9. **ย้อนกลับ**: เอาการกระทำล่าสุดออก (เส้น หรือการใส่รูป) · ไม่มีอะไรให้ย้อน → ปิด
10. **ล้าง**: เอาทุกเส้นและรูปพื้นหลังออก · ว่างอยู่แล้ว → ปิด
11. **ใส่รูป**: เลือกไฟล์ (`accept="image/*"`) → รูปเป็นพื้นหลัง ย่อให้พอดี canvas (contain · ไม่ยืด) · ใส่ใหม่แทนรูปเดิม · ย้อนกลับได้ · ไฟล์ที่ไม่ใช่รูปหรือเปิดไม่ได้ → ข้อความ `ใส่ได้เฉพาะรูป` และไม่เปลี่ยนอะไร
12. **ส่งคำตอบ**: ปิดเมื่อ canvas ว่าง (ไม่มีเส้นและรูป) หรือห้องกำลังรอคำตอบ (`busy`) · กดแล้ว: วาดพื้นขาว + รูปพื้นหลัง + เส้นทั้งหมดลง canvas ส่งออก → PNG → `File("คำตอบ.png", image/png)` → `send({text: null, image})` ของห้อง (เหมือน Composer · `room-photo-send.md`) · ไฟล์ใหญ่เกิน `limits.max_image_mb` → ข้อความเดียวกับ Composer (TM-21) และไม่ส่ง
13. หลังส่ง: สิ่งที่เขียนยังอยู่ (แก้แล้วส่งใหม่ได้ เช่น ขาดวิธีทำ หรือการ์ดยืนยันกด "ถ่ายใหม่") · ข้อความเล็ก `ส่งแล้ว · แก้แล้วส่งใหม่ได้` จนกว่าจะเขียนหรือแก้อีก

**B · canvas อยู่ท้ายแชทเสมอเมื่อมีโจทย์ค้าง (9 พ.ย. · Jam ลองแล้ว: คุยไปสักพัก canvas เลื่อนพ้นจอ · แทนข้อ 1–2)**

16. canvas อยู่**ท้ายรายการข้อความ** (หลังข้อความล่าสุด รวมจุดกำลังพิมพ์) เมื่อมีการ์ดโจทย์อย่างน้อย 1 ใบ · ผูกกับการ์ดโจทย์ใบล่าสุด · ไม่มีการ์ดโจทย์ → ไม่มี canvas
17. หัวกล่องแสดงโจทย์ตัวเล็ก `โจทย์` + `text_latex` (KaTeX) ให้รู้ว่ากำลังเขียนข้อไหน
18. สิ่งที่เขียน**ไม่หาย**ระหว่างแชท (ข้อความใหม่ไม่ทำให้ canvas เริ่มใหม่) · เริ่มใหม่ว่างเมื่อ `problem_id` ของการ์ดใบล่าสุดเปลี่ยน · การ์ดโจทย์ข้อเดิมซ้ำ (ขาดวิธีทำ · demo-room §2 I ข้อ 6) ไม่ล้างสิ่งที่เขียน
19. การ์ดโจทย์ในแชทยังอยู่ที่เดิม

**C · ตัด `**` ในข้อความ (9 พ.ย. · Jam)**

20. model บางครั้งเขียน `**ตัวหนา**` ซึ่งหน้าแชทไม่ render Markdown · `MessageText` ตัดคู่ `**…**` เหลือแต่ข้อความข้างใน **เฉพาะส่วนที่ไม่ใช่สมการ** (`$…$`, `$$…$$` ไม่แตะ) · `**` ที่ไม่มีคู่คงไว้

**โครงสร้างโค้ด**

14. ตรรกะของภาพเป็น pure function ใน `components/chat/canvasStrokes.ts` (state: เส้น, รูปพื้นหลัง, ประวัติสำหรับ undo, เคยมีปากกาไหม · action: start, move, end, undo, clear, setBackground · ความหนาจากแรงกด · ตัดสินว่าจะเมิน pointer ไหม) · การวาดลง context อยู่ในฟังก์ชันเดียว `drawScene(ctx, scene, size)` · component `AnswerCanvas.tsx` ต่อ pointer event และปุ่มเข้ากับสองอย่างนี้
15. ไม่เพิ่ม dependency · test mock `getContext` และ `toBlob` เอง (jsdom วาด canvas ไม่ได้)

## 3. Inputs and outputs

| | Type | ตัวอย่าง |
|---|---|---|
| Input | การ์ดโจทย์ใบล่าสุด (`ChatMessage.problem`) | `{problem_id: "p1", text_latex: "x^2 - 49", …}` |
| Input | pointer events บน canvas | `{pointerType: "pen", pressure: 0.6, isPrimary: true, x, y}` |
| Output | `SendPayload` ของห้อง | `{text: null, image: File("คำตอบ.png", image/png)}` |

## 4. Acceptance criteria

ทุกข้อเป็น Vitest + Testing Library (jsdom) · `getContext` และ `toBlob` ถูก mock · ค่าของ UI (`CANVAS_HEIGHT_PX`, `PEN_WIDTH_PX`, `ERASER_WIDTH_PX`) อ่านจากโมดูล ไม่พิมพ์ตัวเลขใน test

**ขึ้นเมื่อไหร่**
- **AC-1 (TM-06)** มีการ์ดโจทย์ → มี `role="form"` ชื่อ `เขียนคำตอบ` (ไม่ใช่ region: test ของการ์ดโจทย์ใน `ChatRoomStream.test.tsx` นับทุก region · Jam เลือก 9 พ.ย.) ใต้การ์ด พร้อมปุ่มปากกา ยางลบ ย้อนกลับ ล้าง ใส่รูป ส่งคำตอบ · ไม่มีการ์ดโจทย์ → ไม่มี canvas
- **AC-2** การ์ดโจทย์ 2 ใบ → canvas อยู่ใต้ใบที่ 2 เท่านั้น
- **AC-3** การ์ดโจทย์ใบใหม่มาระหว่าง stream → canvas ใต้ใบใหม่ว่าง (ส่งคำตอบปิด)

**ตรรกะ (pure · `canvasStrokes.ts`)**
- **AC-4** start → move → end ได้ 1 เส้นที่มีจุดตามลำดับ · undo เอาออก · clear ว่าง · undo หลัง clear ไม่คืน (clear ล้างประวัติด้วย)
- **AC-5** ไม่วาดตามฝ่ามือ: ก่อนมีปากกา `touch` วาดได้ · หลังมีเส้น `pen` 1 เส้น `touch` ถูกเมิน · `mouse` วาดได้เสมอ · pointer ที่ไม่ใช่ primary ถูกเมิน
- **AC-6** ความหนา: `pen` แรงกด 0.5 → `PEN_WIDTH_PX` · 1.0 → 2 เท่า · 0.1 → 0.5 เท่า (ขอบล่าง) · `mouse` และ `touch` → `PEN_WIDTH_PX` เสมอ · ยางลบ → `ERASER_WIDTH_PX`
- **AC-7** setBackground แทนรูปเดิม และ undo กลับเป็นรูปเดิม (หรือไม่มี)
- **AC-8** drawScene: พื้นขาว → รูปพื้นหลังแบบ contain (ตำแหน่งและขนาดคำนวณให้ไม่ยืด) → เส้นตามลำดับ · เส้นยางลบใช้ `globalCompositeOperation = "destination-out"` บนชั้นเส้น (รูปพื้นหลังไม่ถูกลบ)

**การใช้งาน (component)**
- **AC-9 (TM-06)** ลากเมาส์บน canvas → ส่งคำตอบเปิด · กดส่ง → `onSend` ได้ `{text: null, image}` ที่ `image` เป็น `File` ชื่อ `คำตอบ.png` ชนิด `image/png`
- **AC-10** ห้อง `busy` → ส่งคำตอบปิด · canvas ว่าง → ส่งคำตอบปิด · ย้อนกลับและล้างปิดเมื่อไม่มีอะไร
- **AC-11 (TM-21)** ไฟล์ที่ส่งออกใหญ่กว่า `limits.max_image_mb` → ข้อความรูปใหญ่เกินของ Composer และไม่เรียก `onSend` · เท่ากับเพดานพอดี → ส่งได้
- **AC-12** ใส่รูป: เลือกไฟล์รูป → รูปเป็นพื้นหลังและส่งคำตอบเปิด · เลือกไฟล์ที่ไม่ใช่รูป → `ใส่ได้เฉพาะรูป` และไม่เปลี่ยน
- **AC-13** หลังส่ง: เส้นยังอยู่และขึ้น `ส่งแล้ว · แก้แล้วส่งใหม่ได้` · เขียนต่อ → ข้อความหาย
- **AC-14 (a11y)** ทุกปุ่มมี `aria-label` · ปากกา/ยางลบมี `aria-pressed` ถูกตัว · canvas มี `aria-label` บอกให้เขียนวิธีทำ
- **AC-15** ห้องเดิม (`ChatRoom`) ส่งข้อความจาก canvas ผ่าน `sendMessage` เดียวกับ Composer · ขึ้น bubble ของผู้ใช้ที่มีชื่อไฟล์ `คำตอบ.png`

**B, C**
- **AC-16** การ์ดโจทย์ → token ของ tutor 2 ข้อความตามมา → canvas อยู่หลังข้อความสุดท้าย (ไม่ใช่ติดใต้การ์ด) · เขียนไว้ก่อนแล้วข้อความใหม่มา → ส่งคำตอบยังเปิด (สิ่งที่เขียนยังอยู่)
- **AC-17** หัวของ canvas แสดง `โจทย์` และ LaTeX ของการ์ดใบล่าสุด
- **AC-18** การ์ดโจทย์ข้อเดิม (`problem_id` เดิม) มาซ้ำ → สิ่งที่เขียนยังอยู่ · `problem_id` ใหม่ → ว่าง
