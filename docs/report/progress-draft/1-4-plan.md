## 1.4 แผนการดำเนินงาน

### 1.4.1 วิธีการดำเนินงาน

ทีมแบ่งการทำงานในภาคการศึกษาที่ 1 เป็น sprint ละ 2 สัปดาห์ ทุก sprint มีเป้าหมายและการสาธิตผลงานเมื่อจบ sprint โดย sprint แรกเป็นการเตรียมโครงสร้างพื้นฐานและ SRS ส่วน sprint ที่ 2 และ 3 ใช้ทำ PoC ในส่วนที่มีความเสี่ยงทางเทคนิคสูง ได้แก่ การอ่านลายมือ การสกัดหัวข้อ การตรวจคำตอบ และการนำระบบขึ้นให้บริการอัตโนมัติ ก่อนพัฒนาส่วนนั้นจริง และ sprint ที่ 4 เชื่อมทุกส่วนให้ผู้ใช้ใช้งานได้ตั้งแต่สมัครสมาชิกจนจบการติว ในภาคการศึกษานี้ทีมเน้นให้ฟังก์ชันหลักทำงานได้ถูกต้องก่อน ส่วนการออกแบบหน้าจอฉบับสมบูรณ์และความสามารถที่เหลืออยู่ในแผนของบทที่ 5

การพัฒนาแต่ละความสามารถใช้แนวทาง Spec-Driven Development และ Test-Driven Development โดยเขียน feature specification ก่อน แปลง acceptance criteria เป็น test ให้สมาชิกตรวจ test แล้วจึงเขียนโค้ดจนผ่านการทดสอบ โค้ดทุกชิ้นต้องผ่าน Continuous Integration (CI) ก่อน merge เข้า branch หลัก และระบบ deploy ขึ้น staging อัตโนมัติหลัง merge

สมาชิกทีมอยู่ต่างเขตเวลากัน ทีมจึงตกลงให้สมาชิกที่ทำงานในช่วงที่ผู้อื่นไม่อยู่ รับงานของสมาชิกคนอื่นไปทำต่อได้ โดยบันทึกความคืบหน้าของทุกงานไว้ใน repository เพื่อให้ผู้ที่กลับมาทำต่อจากจุดเดิมได้ และเจ้าของส่วนงานตรวจผลงานย้อนหลัง
