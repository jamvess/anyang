# 2.6 การนำทฤษฎีมาใช้ในการออกแบบ (Design Rationale) · ที่พักข้อมูล

Jam 28 พ.ย.: ใช้ตารางท้ายบทแทนย่อหน้า "ระบบนำมาใช้" ในแต่ละหัวข้อย่อย (แบบตัวอย่าง ENG) · ทำตารางจริงหลัง 2.3–2.5 เสร็จ · คอลัมน์: งานวิจัย · หลักการ · การออกแบบของระบบ · หัวข้อในบทที่ 3 · สถานะ (ใช้งานได้ / อยู่ระหว่างพัฒนา)

| 2-1-learning-theory.md | 2.1.1 การฝึกดึงความรู้ (Retrieval Practice) | การติวในระบบเป็นการทำโจทย์ทีละข้อในบทสนทนา ไม่ใช่การให้อ่านชีท และทุกหัวข้อเริ่มด้วยโจทย์วัดความรู้เดิม (Probe) ก่อนการอธิบาย (หัวข้อ 3.5) ทั้งนี้ การเดินขั้น Probe, Teach และ Verify ในห้องติวอยู่ระหว่างพัฒนา |
| 2-1-learning-theory.md | 2.1.2 การทบทวนแบบเว้นระยะ (Spaced Practice) | หัวข้อที่ผู้เรียนผ่านแล้วจะถูกนำกลับมาทบทวนเป็นรอบ โดยระยะห่างของแต่ละรอบคำนวณจากจำนวนวันที่เหลือก่อนสอบ (หัวข้อ 3.6) ส่วนนี้อยู่ระหว่างพัฒนา |
| 2-1-learning-theory.md | 2.1.3 การติวแบบตัวต่อตัว (One-to-one Tutoring) | ระบบตรวจคำตอบทีละบรรทัด ชี้บรรทัดแรกที่ผิดพร้อมประเภทความผิด แล้วอธิบายทันทีและใบ้ทีละระดับก่อนเฉลย จากนั้นให้โจทย์แบบเดียวกันเพื่อยืนยันความเข้าใจ ซึ่งเป็นการนำองค์ประกอบของการติวแบบตัวต่อตัวและ mastery learning มาทำผ่านบทสนทนากับ AI (หัวข้อ 3.5 และ 3.7) ทั้งนี้ การให้โจทย์แบบเดียวกันเพื่อยืนยันความเข้าใจอยู่ระหว่างพัฒนา |
| 2-1-learning-theory.md | 2.1.4 ตัวละครช่วยสอน (Pedagogical Agent) | AI Buddy ทำหน้าที่เป็นเพื่อนร่วมเรียนในบทสนทนาเดียวกับ AI Tutor โดยสื่อสารด้วยข้อความ ให้กำลังใจเมื่อผู้เรียนทำผิดติดกัน และชวนให้ผู้เรียนอธิบายวิธีคิด โดยระบบกำหนดจังหวะที่ AI Buddy พูดได้ด้วยกฎ เพื่อไม่ให้รบกวนผู้เรียนขณะคิด (หัวข้อ 3.5) โดย AI Buddy อยู่ระหว่างพัฒนา ทั้งนี้ ผลของ pedagogical agent ในระดับมหาวิทยาลัยมีขนาดเล็กกว่าระดับอื่น ทีมจึงวัดผลของ AI Buddy ในการทดสอบกับผู้ใช้ (บทที่ 5) แทนการสันนิษฐานว่าได้ผล |
| 2-2-knowledge-tracing.md | 2.2.1 Bayesian Knowledge Tracing | ระบบใช้ BKT ประเมินความเข้าใจรายหัวข้อ เพราะ (1) ในช่วงแรกยังไม่มีข้อมูลผู้ใช้สำหรับ train model ที่ซับซ้อนกว่า (2) parameter ทุกตัวมีความหมายที่อธิบายให้ผู้เรียนและกรรมการตรวจสอบได้ และ (3) ใช้ค่าเริ่มต้นและขอบของ parameter จากงานวิจัยได้ทันที ทีมวางแผน calibrate parameter ด้วยข้อมูลจากการทดสอบกับผู้ใช้ และเปรียบเทียบกับ logistic model เมื่อมีข้อมูลเพียงพอ (หัวข้อ 3.6 และบทที่ 5) |
| 2-2-knowledge-tracing.md | 2.2.2 Mastery Learning และเกณฑ์การผ่าน | เกณฑ์ผ่านของระบบมีสามเงื่อนไขพร้อมกัน คือ ค่า mastery ถึง 0.95 ผู้เรียนเคยทำโจทย์ระดับความยากตามเป้าของหัวข้อได้ถูกด้วยตนเอง และทำทุกทักษะย่อยที่เคยออกข้อสอบได้ถูกอย่างน้อยหนึ่งครั้ง โดยระบบจำกัดค่า mastery ที่ใช้ตัดสินด้วยเพดานตามระดับความยากสูงสุดที่ผู้เรียนทำถูก เพื่อแก้ข้อจำกัดเรื่องความยากของโจทย์ข้างต้น (หัวข้อ 3.6) |
| 2-2-knowledge-tracing.md | 2.2.3 ความพร้อมสอบ (Readiness) | ความพร้อมสอบคำนวณจาก mastery ของแต่ละหัวข้อถ่วงน้ำหนักด้วยความสำคัญของหัวข้อที่ได้จากข้อสอบเก่า และแสดงเป็นการ์ดความก้าวหน้าในบทสนทนา ทีมจะเปรียบเทียบค่านี้กับคะแนนสอบจริงของผู้เรียนในการทดสอบนำร่อง (หัวข้อ 1.2 วัตถุประสงค์ข้อ 4) |
| 2-2-knowledge-tracing.md | 2.2.4 การวางลำดับการเรียนรู้ (Learning Path) | ระบบเรียงหัวข้อตาม prerequisite ที่สกัดจากเอกสาร และเลือกหัวข้อถัดไปด้วยกฎที่อธิบายได้จากความสำคัญ ความเข้าใจ และเวลาที่เหลือก่อนสอบ แทนการใช้ reinforcement learning ที่ต้องใช้ข้อมูลจำนวนมาก และเมื่อผู้เรียนทำโจทย์ทักษะเดียวกันครบ 10 ข้อในวันเดียวโดยยังไม่ผ่าน ระบบจะพักทักษะนั้นและพาไปทบทวนความรู้พื้นฐานก่อน (หัวข้อ 3.5) ทั้งนี้ ทีมพัฒนาโมดูลเลือกหัวข้อและการพักทักษะพร้อม test แล้ว และอยู่ระหว่างเชื่อมต่อกับห้องติว |
