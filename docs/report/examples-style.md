## สำนวนที่ใช้ร่วมกัน

- เรียกทีมว่า "คณะผู้จัดทำ" · อ้างรูปและตารางว่า "จากภาพที่ X …", "ดังแสดงในตารางที่ X", "ดังตารางที่ X"
- รูปที่ยืมมามีบรรทัด "ที่มา: URL" ใต้คำบรรยายรูป (THAI1, THAI2)
- ทับศัพท์อังกฤษในวงเล็บหลังคำไทย เช่น "การจัดเก็บข้อมูล (Database)" · หรือใช้คำอังกฤษตรงๆ เช่น Use Case Diagram, Functional Requirements
- รายการใช้ bullet และหัวข้อตัวหนาตามด้วยโคลอน เช่น "**Primary Button:** ใช้สำหรับ…"
- อ้างอิงแบบเลขในวงเล็บเหลี่ยม [n] (THAI2, HDS) หรือ (Author, year)[n] (ENG) · THAI1 แทบไม่อ้างในเนื้อหา

## บทที่ 1

- ทุกเล่ม: ที่มาและความสำคัญ → วัตถุประสงค์ (ข้อ "เพื่อ…") → ขอบเขต (bullet) → แผน (WBS + Gantt แยกภาค 1 และ 2) → ผลที่ส่งมอบภาค 1 และภาค 2
- ENG มีย่อหน้าความเสี่ยงและการรับมือหลัง Gantt · THAI1 มีกลุ่มเป้าหมายและสภาพแวดล้อมในขอบเขต
- Gantt: ตารางสัปดาห์ × งาน ระบายสี พร้อมคอลัมน์ผู้รับผิดชอบ (THAI1, THAI2) · ENG ใช้สีต่อคน + legend

## บทที่ 2

- THAI1: นิยามแบบ "X คือ …" 1–2 ย่อหน้าต่อทฤษฎี + รูป · เครื่องมือเป็นรายการบรรทัดเดียวต่อตัว แบ่งกลุ่ม (ภาษา, frontend, backend, database, DevOps) · ผลิตภัณฑ์ที่มีอยู่ย่อหน้าละตัว + ภาพหน้าจอ + ตาราง ✓/×
- THAI2: นิยาม → ขั้นตอนพร้อมรูป → ปิดด้วย "ดังนั้น … สามารถนำมาประยุกต์ใช้…" · เครื่องมือย่อหน้าละตัว · งานวิจัยและผลิตภัณฑ์ย่อหน้าละตัว + ภาพ + ตารางเปรียบเทียบ + ย่อหน้าสรุปว่าของเราต่างอย่างไร
- HDS: นิยามอัลกอริทึม + รูป · งานวิจัยย่อหน้าละงานพร้อมตัวเลข (จำนวนเคส, MAE) + รูปจากงานนั้น · ปิดด้วยการแบ่งแนวโน้มงานวิจัยและความต่างของเรา
- ENG: อ้างงานวิจัยหนาแน่น มีสมการ วิจารณ์จุดอ่อนงานเดิม · 2.5 Challenges · 2.6 Design Rationale เป็น bullet "**หัวข้อ:** วิธีแก้" · 2.7 Preliminary design

## บทที่ 3 (การออกแบบและวิธีดำเนินงาน)

- **ความต้องการ:** THAI1 สัมภาษณ์ 3 กลุ่ม (ข้อมูล / ภาระงาน / ข้อมูลสำคัญ) + Customer Journey Map · THAI2 แบบสอบถาม + สัมภาษณ์ + proto-persona
- **Functional / Non-functional requirements:** bullet จัดกลุ่มตามระบบย่อย ขึ้นต้น "ระบบสามารถ…" หรือ "ผู้ใช้สามารถ…" · NFR แยกหัว ประสิทธิภาพ, scalability, reliability, security พร้อมตัวเลข (เช่น ตอบภายใน 10 วินาที, uptime 90%)
- **Use case:** diagram + ตารางต่อ use case · THAI1 ใช้หัวแถวอังกฤษ (Actor, Goal, Preconditions, Main Success Scenario, Extensions, Postcondition) · THAI2 ใช้หัวไทย (ชื่อกรณีการใช้งาน, ผู้มีส่วนเกี่ยวข้อง, เป้าหมาย, เงื่อนไขก่อนหน้า, สถานการณ์หลัก, ส่วนขยาย (a)(b), เงื่อนไขภายหลัง)
- **Sequence / Activity diagram:** รูป + ย่อหน้า "จากภาพที่ X กระบวนการเริ่มจาก…" หรือรายการ "ลำดับสถานการณ์ที่เกิดขึ้น" เป็นข้อ 1, 2, 3
- **สถาปัตยกรรม:** รูปเดียว + หัวข้อย่อยต่อ layer (THAI1: Client, API, AI/ML, Storage) หรือย่อหน้าต่อส่วน (THAI2: frontend, core backend, อุปกรณ์, OCR service) บอกภาษา framework และ protocol
- **ฐานข้อมูล:** ER diagram + ตาราง data dictionary ต่อตาราง (ชื่อคอลัมน์ · ประเภทข้อมูล · Key · คำอธิบาย) พร้อมคำอธิบายหนึ่งย่อหน้าต่อตาราง
- **UX/UI:** persona, sitemap, design system (สี, typography ตาราง, component พร้อม state), หน้าจอเป็นชุด A–E พร้อม "คำอธิบายส่วน A — …"
- **การพัฒนา:** THAI1 ภาพหน้าจอ terminal/config, ตารางเลือก model (ชื่อ · ประเภท · หน้าที่ · เหตุผล), แผนภาพ pipeline + ตัวอย่างผลลัพธ์ JSON, ภาพ Postman, ภาพหน้าเว็บพร้อมย่อหน้า
- **ENG:** System architecture, model selection, mechanism (bullet ตัวหนา), development strategies, evaluation plan (metrics, comparisons), datasets
- **THAI2 3.9–3.10:** ผลการดำเนินงาน / ปัญหา / ข้อจำกัดที่พบ · แผนภาค 2 เป็น Gantt + คำอธิบายรายขั้นพร้อมวิธีทดสอบ (manual E2E, usability test 5 คนต่อกลุ่ม, think-aloud, SUS)
