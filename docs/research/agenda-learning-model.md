## 1 · BKT ระดับหัวข้อ หรือระดับ skill · เสนอเปลี่ยน

**ตอนนี้:** mastery มี 1 ค่าต่อ **หัวข้อ** (`topic_progress.mastery`) · แต่เงื่อนไข Done ตรวจ **ทุก skill** ที่ออกสอบ และ planner ประมาณเวลาเป็น **ต่อ skill** อยู่แล้ว (`learning-model.md` §1, §4, §6)

**หลักฐาน:** Pelánek (2018) ชี้ว่า 0.95 ของ BKT จะแปลว่า "มั่นใจ 95% ว่ารู้แล้ว" ได้ก็ต่อเมื่อหน่วยที่วัดละเอียดพอ · ถ้าหน่วยหยาบ (เช่นหัวข้อ "การแยกตัวประกอบ" ที่มีหลาย skill) ค่าจะผสมระหว่าง "รู้แค่ไหน" กับ "มั่นใจแค่ไหน" จนความหมายเพี้ยน · ตัวอย่างในระบบเรา: ตอบถูก 3 ข้อติดใน skill เดียว mastery ของทั้งหัวข้อจะถึง 0.986 ทั้งที่ยังไม่เคยเจอ skill อื่น

**ทางเลือก**

| | ทำอะไร | ข้อดี | ข้อเสีย |
|---|---|---|---|
| ก | คงไว้ระดับหัวข้อ | ง่าย ไม่ต้องแก้ spec | 0.95 ไม่มีความหมายชัด · ต้องพึ่ง skill coverage อย่างเดียว |
| ข | **BKT ต่อ skill** · ค่าระดับหัวข้อ = ค่าเฉลี่ยถ่วงด้วย `exam_freq` ของ skill | ตรงกับงานวิจัย · Done ตรวจ "ทุก skill ถึงเกณฑ์" ได้ตรงๆ | ต้องตกลงสูตรรวมเป็นค่าหัวข้อ · ข้อมูลต่อ skill น้อยลง |
| ค | BKT ต่อ skill แต่แสดงผลแค่ระดับหัวข้อ | ผู้เรียนเห็นเหมือนเดิม | ยังต้องตกลงสูตรรวมเหมือนข้อ ข |

**ข้อเสนอ:** ข · ต้องตัดสินด้วยว่าค่าหัวข้อใช้ค่าเฉลี่ยถ่วง `exam_freq` หรือค่าต่ำสุดของ skill

**ถ้าเลือก ข หรือ ค ต้องแก้:** `learning-model.md` §1, §4, §5 · `ai-orchestration.md` §2.2.6 (เพิ่ม mastery ต่อ skill ใน `topic_progress.skill_coverage` หรือ column ใหม่) · migration ใหม่ (Junior) · `config/learning.yaml` ไม่ต้องเปลี่ยนค่า

## 2 · BKT หรือ logistic model · คุย ไม่เปลี่ยนใน MVP

**ตอนนี้:** BKT ใช้ค่า fixed (`bkt.*`) และจะ fit `p_init`, `p_transit` ด้วย pyBKT หลัง Alpha

**หลักฐาน:** Gervet et al. (2020) เทียบ 9 datasets แล้ว BKT แพ้ logistic regression (เช่น PFA) ใน data ขนาดกลาง · แต่ Khajah et al. (2016) พบว่า BKT ที่ขยายบางส่วนทำได้พอๆ กับ deep model และอธิบายได้ง่ายกว่า · Pelánek (2017) สรุปว่าการเลือกโมเดลขึ้นกับบริบท

**ข้อเสนอ:** MVP ใช้ BKT ต่อ เพราะยังไม่มีข้อมูลให้ fit โมเดลอื่น และ code ต้องอธิบายได้ว่าทำไมระดับเปลี่ยน (หลัก "Code ตัดสินใจ, LLM พูด") · หลัง Alpha เทียบ BKT (pyBKT) กับ PFA บนตาราง `attempts` ด้วย AUC และ RMSE แล้วเลือกตามผล

**คำถามถึงอาจารย์:** แผนนี้พอสำหรับรายงานไหม หรือควรเทียบตั้งแต่ pilot

## 3 · ความพร้อม %: กันมั่นใจเกิน + validate กับคะแนนจริง · คุยทิศทาง

**ตอนนี้:** ความพร้อม = Σ(r × mastery) ÷ Σr แสดงใน progress card ทุกครั้งที่เปิด session (`learning-model.md` §5, TM-15) · ยังไม่เคยเทียบกับคะแนนสอบจริง

**หลักฐาน:** Dunlosky & Rawson (2012) ผู้เรียนที่มั่นใจเกินจะหยุดทวนเร็วแล้วได้ผลแย่ · Bull & Kay (2016) ให้กรอบออกแบบหน้าจอที่ผู้เรียนเห็นโมเดลของตัวเอง · Feng et al. (2009) ข้อมูลระหว่างติวทำนายคะแนนสอบได้

**คำถาม**
1. **May:** progress card ควรแสดงอะไรคู่กับ % เพื่อไม่ให้อ่านเป็นคะแนนสอบ เช่น "ยังไม่ผ่าน 3 หัวข้อ ★★★" หรือช่วงความไม่แน่นอน
2. **Jam:** pilot จะเก็บคะแนนสอบจริงหลังสอบไหม (ถามในแอป หรือ Google Form) เพื่อดูว่าความพร้อมสัมพันธ์กับคะแนนแค่ไหน

**ข้อเสนอ:** คำอธิบายใต้ตัวเลขบอกจำนวนหัวข้อ ★★★ ที่ยังไม่ผ่านเสมอ · pilot เก็บคะแนนสอบจริงด้วย Google Form (ไม่ต้องสร้าง feature)
